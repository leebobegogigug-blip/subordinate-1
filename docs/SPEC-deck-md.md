# deck.md 형식 명세 (deck_md 1)

- 상태: T16 · 2026-11-03. 기획 5판 (docs/PLAN.md 00) 의 결과물 `deck.md` 의 계약이다. 스킬 (T17) 이 이대로 쓰고, 사람이 이대로 검토하고, 기성품 (pandoc · Presenton) 이 이것을 받는다.
- 표기: [실험] 이 저장소에서 직접 돌려 본 것 (pandoc 3.1.3 · python-pptx 1.0.2 로 결과 PPTX 를 열어 봄 · LibreOffice 로 그려 봄) · [문헌] docs/PLAN.md 와 M0 결과 · [추정] 실험에서 늘린 판단 · [미확인] 확인하지 못한 것 · [제안] 근거 없이 정한 문턱.
- 예시: [docs/examples/deck_synthetic.md](examples/deck_synthetic.md) (합성 이상 보고) · 반례: [docs/examples/deck_counterexamples.md](examples/deck_counterexamples.md). `tests/test_deck_md_example.py` 가 아래 규칙 DM-01 – DM-14 중 기계로 잴 수 있는 것을 둘에 대 본다.

## 1 모양

```text
---                                   머리말 (YAML)
title: … 
---
## 요약 › PRD_B 두께가 9/16 부터 1.2 nm 올라 USL 을 넘었다
                                      장 = 2단계 제목 = 절 머리 › 한 문장 주장
- 현상: … [f003]                      글머리 한 줄 = 문장 하나 + 꼬리표
## 현상 › …
:::::: columns                        그림이 있는 장은 두 단
::: column
![img2 · PRD_B 두께 lot 추세](그림/경로.png)
:::
::: column
근거: 파일 · 기간 · n · 거르기 · 집계 · 검정 [f003 · f011]
- … [f003]
:::
::::::
::: notes                             발표자 노트 (해석의 추론)
해석 근거: …
:::
## 한계 › …                          지울 수 없다
## 부록 › …                          근거 목록 (id · 원문)
```

- 쓰는 마크다운은 2단계 제목 · 한 단계 글머리 (`- `) · 그림 줄 · `근거:` 줄 · `::: notes` · `:::::: columns` 뿐이다. 1단계 제목 (`# `) · 표 · 중첩 글머리 · 굵게 · 링크 · HTML 은 쓰지 않는다 [제안 — 둘 다 받게 하려는 것].
- 모든 제목 앞뒤에 빈 줄을 둔다. 빈 줄이 없으면 pandoc 이 제목으로 읽지 않아 장이 앞 장에 붙는다 [실험].
- 파일은 UTF-8 하나다. 그림은 옆 폴더의 원본 파일을 상대 경로로 가리킨다.

## 2 머리말

| 칸 | 값 | pandoc 이 쓰나 [실험] |
|---|---|---|
| `title` | 보고 이름 | 표지 장의 제목 자리 |
| `subtitle` | 한 줄 (작성자를 넣으려면 여기에) | 표지 장의 부제 자리 |
| `date` | `YYYY-MM-DD` | 표지 장의 날짜 자리 |
| `deck_md` | `1` (형식 판) | 안 씀 |
| `type` | `이상 보고` · `실험 결과` · `정기 보고` | 안 씀 |
| `audience` | 독자 (팀 · 팀장 · 경영진 · 다른 부서) | 안 씀 |
| `data_class` | `synthetic` · `real` | 안 씀 |
| `sources.facts` · `sources.interview` | 스킬이 읽은 사실 목록 · 인터뷰 답 파일의 이름 (없으면 `없음`) | 안 씀 |

- `author` 는 쓰지 않는다 (DM-01 이 막는다). pandoc 이 부제 뒤에 띄어쓰기 없이 붙인다 [실험]. 작성자는 `subtitle` 에 넣는다.
- 안 쓰는 칸은 표지에 나오지 않는다 [실험].

## 3 절과 장

- 절은 따로 쓰지 않고 장 제목의 머리로 쓴다: `## 현상 › PRD_B 두께 평균이 9/16 부터 +1.2 nm 올랐다`. 머리 이름과 순서: `요약` › `현상` › `현상 범위` › `분석` › `의견` › `한계` › `부록` (P-05). `현상 범위` 만 빼도 된다. 같은 머리의 장은 붙어 있고, 머리가 없거나 목록 밖의 이름이거나 순서가 거꾸로면 어긴 것이다 (DM-02).
- 머리 뒤 ` › ` 다음이 주장이다. 주장은 완결된 한 문장이다 (P-02). `다` 로 끝나고, 공백을 넣어 40자 안이며 (머리는 세지 않는다) [제안], 꼬리표 · 괄호를 달지 않는다. 숫자를 하나 넣기를 권한다.
- 머리 덕에 제목만 이어 읽어도 현상 › 분석 › 의견 의 흐름이 보이고, 절이 장 위에도 남는다. 1단계 제목은 pandoc 이 절마다 구분 장을 끼워 넣어 (예시 17장 중 7장) 쓰지 않는다 [실험].
- 제목의 숫자는 그 장 몸통이 인용한 사실 · 답에 있는 값이어야 한다 (`[추정]` 값은 제목에 못 올린다).
- 제목만 이어 읽어 이야기가 되어야 한다 (P-06 ghost deck). 본문 장 (요약 – 한계) 은 9장 안을 권한다 [제안].
- 결과 장 하나 = 증거 하나 (P-03). 그림은 장마다 하나다. 그림 둘을 비교하려면 두 장으로 나누거나 사용자가 합친 그림을 받는다 — 한 장에 그림 둘과 글을 함께 두면 pandoc 에서 겹친다 [실험].

## 4 그림과 근거 줄

- 그림 줄: `![imgN · 무엇을 보이나](상대 경로)`. 대체 글은 `imgN · ` 으로 시작하고 pandoc 이 그림 아래 설명 글상자로 넣는다 [실험].
- 경로의 파일 이름은 받은 그림 그대로다. 그림을 고치거나 다시 저장하거나 화살표를 그린 새 파일을 만들지 않는다 (P-08). 강조가 필요하면 노트에 적고 사람이 PowerPoint 도형으로 얹는다.
- 그림이 있는 장은 `:::::: columns` 두 단으로 쓴다. 왼쪽 단에는 그림 줄만, 오른쪽 단에는 근거 줄 › 글머리. 그림과 글을 한 단 (또는 단 없이) 에 두면 pandoc 이 그림과 글 자리를 같은 자리에 겹쳐 놓는다 [실험].
- 근거 줄 (P-04): `근거: 파일 · 기간 · n · 거르기 · 집계 · 검정 [id …]` — 여섯 칸을 ` · ` 로 나누고, 첫 칸은 그림 파일 이름이다. 모르는 칸은 `미확인` 이라고 쓴다 (`거르기 미확인`). 숫자 규칙 (6) 을 똑같이 따른다.
- 근거 줄이 그림 아래가 아니라 오른쪽 단 맨 위에 오는 것은 pandoc 때문이다: 그림 아래에 둔 글은 그림과 겹친다 [실험].

## 5 문장의 종류와 출처 id

글머리 한 줄이 문장 하나다. 줄 끝의 꼬리표가 종류 (P-01) 와 출처를 함께 적는다.

| 종류 | 쓰는 법 | 출처 조건 |
|---|---|---|
| 사실 | `- … [f003]` · `- … [f003 · a05]` | id 하나 이상 (사실 · 그림 · 답) |
| 해석 | `- … [해석 · f005 · f006]` | 사실 · 그림 id 둘 이상 + 노트에 `해석 근거:` 한 줄 |
| 의견 | `- … [의견 · a02 · a03]` | 답 id 하나 이상. `요약` · `의견` 장에만 |
| 추정 | `- … 약 103.7 nm 로 읽힌다 [추정 · img2]` | 그림 id. 그림에서 읽은 숫자 전용 (K3) |
| 미확인 | `- [미확인] 무엇이 없나` (까닭 id 를 끝에 달아도 된다) | 없음 — 지어서 채우지 않는다 (I-04) |

- id 모양: 사실 `f` + 세 자리 (`f003`) · 그림 `img` + 번호 · 인터뷰 답 `a` + 두 자리 (`a02`). 스킬이 매기고, 같은 id 를 다른 것에 다시 쓰지 않는다.
- 사실은 사실 목록 (분석 도구의 요약 · 사용자가 붙여 넣은 숫자) 에서, 답은 사용자가 확인한 답 요약에서 온다 (I-07). 사용자가 말로 준 숫자는 답 id 를 단 사실이다 (리스크 24).
- `의견` 장의 글머리는 모두 의견이거나 `[미확인]` 이다. 사실 · 해석은 그 앞 장에 둔다.
- `[미확인]` 은 글머리 맨 앞에만 쓴다. 제목 · 근거 줄에는 쓰지 않는다 (근거 줄은 `미확인` 낱말).
- 꼬리표는 장 위에 보이게 남긴다. 까닭은 7 에 있다.

## 6 숫자

- 장 위의 숫자 (몸통 · 근거 줄 · 노트) 는 같은 줄에 출처 id 가 있고, 그 값이 인용한 사실의 글 · 값 · n 이나 답의 글에 그대로 있다. 없으면 쓰지 않거나 사용자에게 묻는다 (V-03 의 뜻).
- 날짜 · 번호도 숫자다 (`9/16` 은 `2026-09-16` 의 9 · 16 과 맞춘다). 영문으로 시작하는 이름 (`EQ-03` · `PRD_B` · 파일 이름) 안의 숫자는 숫자로 세지 않는다.
- 그림에서 읽은 숫자는 `[추정 · imgN]` 꼬리표로만 장에 오른다. 그림 id 만 단 줄에 숫자가 있으면 어긴 것이다. 추정 값은 한계 장에 `[미확인]` 으로도 남긴다 (I-06).
- 계산한 값 (차이 · 비율) 은 사실 목록에 그 값이 있을 때만 쓴다. 스킬이 셈을 해 새 숫자를 만들지 않는다 [제안 — 숫자 출처를 하나로 두려는 것].

## 7 결정 — 종류와 출처는 장 위에, 추론은 노트에

- 꼬리표를 노트에만 두면 장이 깨끗하다. 그래도 장 위에 둔다. 근거:
  1. pandoc 은 `[f003]` · `[해석 · f002 · f003]` 를 글자 그대로 둔다 (링크로 읽지 않는다) [실험: AST 의 `Str "[f003]"`].
  2. `::: notes` 는 pandoc 에서 발표자 노트로 간다 [실험: 3장 중 3장]. Presenton 이 노트를 받는지 · 버리는지는 모른다 [미확인]. 노트에만 둔 근거는 소리 없이 사라질 수 있고, 장 위의 꼬리표는 사라지면 눈에 보인다.
  3. P-04 의 뜻 — 검토 화면 없이 출력물만 보는 상사의 첫 질문 (어디서 온 숫자인가) 에 장이 스스로 답한다 [문헌].
  4. 사내 LLM 은 정해 준 형식을 지킨다 (K2 · 5/5) [문헌]. 줄 끝 꼬리표 하나는 따르기 쉬운 형식이다 [추정 — 이 꼬리표 자체는 사내에서 시험하지 않았다].
- 해석의 추론 · 강조 메모처럼 발표자만 볼 것은 노트에 둔다 (P-01 의 '노트에 추론'). 노트의 숫자도 6 을 따른다.
- 꼬리표를 마지막에 지울지는 사용자가 정한다. 스킬은 지운 판을 만들지 않는다 — `deck.md` 가 근거의 원본이다.
- 절은 제목 머리로 쓴다 (3). 1단계 제목은 절마다 구분 장을 만들어 (17장 중 7장 [실험]) 엔지니어가 매번 지워야 하고, HTML 주석 (`<!-- 절: 현상 -->`) 은 장이 생기지 않지만 [실험] 결과물과 Presenton 에서 절이 보이지 않는다 [추정]. 제목 머리는 장이 늘지 않고 절이 장 위에 보인다 [실험: 10장 · 구분 장 0].

## 8 한계 장과 근거 목록

- `한계 ›` 장은 지울 수 없다 (P-07). `[미확인]` 글머리가 하나 이상 있다 — 인터뷰에서 '모름 · 나중에' 로 남은 칸, `[추정]` 값, 본문의 `[미확인]` 을 모은다. 정말 없으면 `- [미확인] 없음` 한 줄을 남긴다. 사용자가 빼 달라고 해도 지우거나 부록으로 옮기지 않고, 발표에서 가리려면 PPTX 에서 그 장을 숨기라고 알린다 (P-07 '숨기기만' · DM-11 — T23 에서 고침).
- `부록 ›` 근거 목록 장: 글머리마다 `- id · 원문`. 본문이 인용한 사실 · 답 id 가 모두, 그것만 있고, 원문은 사실 목록 · 답 요약의 글과 같다. 그림 id 는 목록에 없고 그 그림 줄로 풀린다. `deck.md` 하나만 넘어가도 id 가 풀리게 하려는 것이다.
- 근거 목록은 장마다 7줄 안으로 나눈다. 8줄부터 기본 양식에서 넘쳤다 [실험: LibreOffice 렌더 — PowerPoint 렌더는 미확인].
- 글 양: 그림 장의 오른쪽 단은 근거 줄 + 글머리 3줄 안 (예시에서 3줄이 겨우 들어갔다 [실험: 같은 렌더]) · 그림 없는 장은 글머리 5줄 안 [제안].

## 10 넘기기 전 점검표 (스킬이 돌린다)

1. 제목 목록 (머리 포함) 만 뽑아 사용자에게 보이고 '이야기가 됩니까' 를 묻는다. 머리가 요약 › … › 부록 순서인지 본다 (P-06 · DM-02 · DM-03). 고치면 다시 보인다.
2. 숫자마다: 같은 줄에 출처 id 가 있고, 그 출처의 글에 같은 값이 있다. 없으면 지우거나 묻는다 (DM-07).
3. 그림에서 읽은 숫자는 모두 `[추정 · imgN]` 이고 한계 장에도 있다. 제목에는 없다 (DM-08).
4. 의견은 모두 답 id 를 달았고, 사용자가 한 말을 다듬기만 했다. 바꾼 뜻이 있으면 사용자에게 보인다 (DM-09 · I-05).
5. 본문의 `[미확인]` 과 '모름' 답이 한계 장에 모였다. 한계 장이 있다 (DM-11).
6. 그림 줄은 받은 파일 이름 그대로이고, 그림 파일을 만들거나 고치지 않았다 (DM-12 · P-08).
7. 근거 목록이 인용한 id 와 맞고, 원문을 고쳐 쓰지 않았다 (DM-13).
8. 모양: 1단계 제목 없음 · 제목 앞뒤 빈 줄 · 그림 장은 두 단 · 글 양 (8) · 쓰지 않는 문법 없음 (1).
9. 무엇이 저장되는지 말한다: `deck.md` 하나와 그것이 가리키는 그림 경로뿐이다 (W-05). 답 원문은 넣지 않는다.

## 11 pandoc 으로 바꾸기 [실험]

같은 예시를 pandoc 3.1.3 으로 바꾸고 python-pptx 로 열어 보았다. 명령 (Windows 에서는 경로를 큰따옴표로):

```text
cd "<deck.md 가 있는 폴더>"
pandoc deck.md -o deck.pptx
pandoc deck.md --reference-doc="<양식>.pptx" -o deck.pptx
```

| 무엇 | 결과 |
|---|---|
| 장 나누기 | `##` 가 장이다. 예시 → 10장 = 표지 1 · 본문 9 · `Section Header` 0. 제목은 머리째 (`현상 › …`) 제목 자리에 들어간다 |
| 1단계 제목 (쓰지 않음) | 절마다 `Section Header` 구분 장이 생긴다 — 1단계 제목을 쓰던 앞 판은 17장 중 7장이 구분 장이었다 |
| 제목 길이 | 머리를 붙인 9개 제목이 모두 두 줄 안에 들었다 [실험: LibreOffice 렌더] |
| 레이아웃 | 글만 → `Title and Content` (6) · 두 단 → `Two Content` (3) · 표지 → `Title Slide` (1) · 겹친 도형 0 |
| 그림 + 글 (단 없이 · 순서 무관) | 그림 (x 2.47 · y 1.31 · 5.04 × 3.15 in) 과 글 자리 (y 1.31 · 높이 3.71 in) 가 겹친다 |
| 그림 + 글 (두 단) | 그림은 왼쪽 (폭 4.42 in) · 글은 오른쪽 · 겹침 0. 한 단 안에 그림과 글을 함께 두면 다시 겹친다 |
| 그림 둘 | 한 문단에 두면 제목 없는 장이 하나 더 생기고 그 장에는 그림 없이 대체 글만 남는다 · 두 단에 하나씩 두면 나란히 |
| 대체 글 | 그림 아래 설명 글상자 (`imgN · …`) |
| `::: notes` | 발표자 노트 (3장 중 3장) |
| 꼬리표 · `[미확인]` | 글자 그대로. 작은따옴표는 둥근 따옴표로 바뀐다 |
| 그림 경로 | 지금 폴더 기준으로 찾는다. 다른 폴더에서 돌리면 'not found in resource path' 와 함께 종료 99 로 멈추고 PPTX 가 나오지 않는다 (T18 에서 다시 잼 — T16 의 '경고와 함께 그림이 빠진다' 를 고침) → 그 폴더에서 돌리거나 `--resource-path` |

회사 양식 흉내 (K4: 레이아웃 10 · 제목 + 본문/그림 자리표시자를 함께 가진 레이아웃 0) — pandoc 기본 양식에서 레이아웃 하나를 지우고 본문 · 그림 · 부제 자리표시자를 걷어 낸 합성 양식 세 벌:

| 합성 양식 | 결과 |
|---|---|
| 레이아웃 이름을 바꿈 (`사내 양식 01` …) | 종료 0 · 경고 7 ('Couldn't find layout named … Falling back to the default'). pandoc 기본 레이아웃 7개가 양식의 마스터 밑에 들어가고 본문은 그것을 쓴다. 마스터 (배경 · 테마) 는 양식 것이 남는다 (마스터에 단 표시가 결과에 있음). 결과는 기본 양식과 같은 10장 · 구분 장 0 · 노트 3 |
| 위 + 제목 자리표시자까지 없음 | 위와 같다 |
| 표준 이름 (`Title and Content` …) 은 두고 자리표시자만 없음 | **실패** · 종료 63 · 'Could not find a 0th placeholder of type obj' — PPTX 가 나오지 않는다 |

- 회사 양식에 기대할 것 [추정]: 배경 · 색 · 글꼴은 양식 것, 자리 배치는 pandoc 기본. 양식 고유의 레이아웃 (도형 · 글상자로 짠 것) 은 쓰이지 않는다. 양식의 레이아웃 이름이 표준 이름과 같고 자리표시자가 없으면 pandoc 이 멈춘다 — 그때는 양식 사본의 레이아웃 이름을 바꿔 위 첫째 경우로 만든다 [추정: 합성 양식에서만 확인]. 실제 회사 양식의 레이아웃 이름은 모른다 [미확인].
- 회사 양식 위로 옮기는 손 작업 시간은 T22 에서 잰다 (리스크 23).
- 절차는 [docs/USE-pandoc.md](USE-pandoc.md) 를 보십시오.

## 12 Presenton 에 넣기 [미확인]

이 세션에서 Presenton 을 돌리지 못했다. 아래 '형식이 하는 일' 은 정한 것이고, '모르는 것' 은 T18 · T22 에서 채운다.

- 형식이 하는 일: 평범한 마크다운 (제목 · 글머리 · 그림 링크) 만 쓴다. pandoc 전용은 `:::` 울타리 두 가지 (노트 · 두 단) 뿐이다. 꼬리표는 장 위의 글이라, 기성품이 글을 다시 써서 꼬리표나 숫자를 바꾸면 `deck.md` 와 대 보아 드러난다. `deck.md` 가 원본이고 기성품의 결과는 사본이다.
- 모르는 것 [미확인]: 마크다운 파일 올리기 · 붙여 넣기를 받는지 · 우리 장 나눔 (`##`) 과 제목을 그대로 두는지 다시 쓰는지 · YAML 머리말과 `:::` 줄을 글로 보이는지 · 상대 경로 그림을 넣는지 · 노트를 받는지 · 회사 양식을 받는지.
- 넣은 뒤 할 일 [제안]: 제목 목록을 `deck.md` 의 제목 목록과 대 본다 (P-06). 꼬리표 · 숫자가 바뀐 장은 `deck.md` 대로 되돌린다.
- 절차는 [docs/USE-presenton.md](USE-presenton.md) 를 보십시오.
