# deck.md 를 Presenton 에 넣어 PPTX 로 내보내기

`Subordinate–1` 이 써 준 보고 장표 원고 `deck.md` 를 Presenton (오픈소스 AI 발표 생성기) 에 넣어 PPTX 로 내보내는 절차입니다. `deck.md` 의 형식은 [SPEC-deck-md.md](SPEC-deck-md.md) 에 있습니다.

> **알려진 한계.** 회사 양식(템플릿)에 맞추는 일은 이 묶음 밖입니다 ([PLAN.md](PLAN.md) › 00). Presenton 이 회사 양식을 쓸 수 있는지, 손으로 옮기는 데 얼마나 드는지는 [미확인] 이고 사내 시범(T22)에서 잽니다.

> **이 문서는 Presenton 을 직접 돌려 보지 않고 썼습니다.** 아래는 공식 저장소 README 에서 읽은 것 `[문헌]` 과 아직 모르는 것 `[미확인]` 뿐입니다. 데스크톱 앱의 화면 이름 · 칸 이름은 README 에 없습니다. **자료가 밖으로 나가지 않는다는 확인(2절)이 끝나기 전에는 합성 자료 (`docs/examples/deck_synthetic.md`) 로만 시험합니다. 회사 자료를 넣지 않습니다.**

## 1 설치 (관리자 권한 없이)

1. README 의 설치 표에 Windows (x64) 데스크톱 앱 `.exe` 가 있고 받는 곳은 Presenton 공식 사이트의 내려받기 쪽입니다 `[문헌]`. 파일 이름 · 판은 확인하지 못했습니다 `[미확인]`. 저장소는 `https://github.com/presenton/presenton` 입니다.
2. 설치 프로그램이 사용자 단위로 깔리는지, 관리자 권한(비밀번호 · 'UAC' 확인)을 묻는지는 README 에 없습니다 `[미확인]`. **설치 중 관리자 권한을 묻는 창이 뜨면 멈추고 설치하지 않습니다.** 이 길을 쓰지 않습니다.
3. Docker 로 돌리는 길(README 에 `ghcr.io/presenton/presenton:latest`)이 있지만 이 문서는 다루지 않습니다. 관리자 권한이 필요하면 이 길은 쓰지 않습니다. 필요한지는 확인하지 못했습니다 `[미확인]`.
4. 설치가 끝나면 설치한 위치를 적어 둡니다 (6절 지우기에 씁니다).
5. 회사 정책상 새 프로그램에 승인이 필요하면 받고 나서 합니다.

## 2 자료가 밖으로 나가지 않게 (가장 먼저)

실행하기 전에 아래를 설정에서 확인합니다. 하나라도 끌 수 없거나 확인하지 못하면 **합성 자료로만** 씁니다.

1. **LLM 을 사내 OpenAI 호환 주소로.** README 의 이름은 `LLM` (공급자) 을 `custom` 으로 두고 `CUSTOM_LLM_URL` (주소) · `CUSTOM_MODEL` (모델) · `CUSTOM_LLM_API_KEY` (키) 를 쓰는 것입니다 `[문헌]`. 서버가 `POST /v1/chat/completions` 를 받아야 한다고 합니다 `[문헌]`.
   - 주소 모양의 예: `https://llm.example.com/v1` (지어낸 주소입니다. 사내 주소로 바꿉니다). 주소 끝에 `/v1` 이 붙는지는 사내 LLM 안내를 따릅니다 `[미확인]`.
   - 데스크톱 앱에서 이 값을 넣는 화면이 무엇이고 위 이름이 그대로 보이는지는 모릅니다 `[미확인]`. README 는 키를 "앱에서 설정할 수 있다" 고 하고, 소스에서 돌리는 Electron 절에 "내장 백엔드에도 Docker 와 같은 환경 변수가 적용된다" 고 적었습니다 `[문헌]`. 설치판 `.exe` 도 환경 변수를 읽는지는 `[미확인]`.
   - **키는 사내에서 받은 키를 설정 칸에 직접 붙여 넣습니다.** 명령줄 · 환경 변수 설정 명령(`setx` · `set`) · 설정 파일 · 화면 사진 · 이 저장소 어디에도 적지 않습니다. 앱이 키를 파일에 저장한다면 그 파일을 커밋 · 공유하지 않습니다.
2. **다른 공급자를 켜지 않습니다.** 공급자 목록에 `openai` · `google` · `anthropic` · `openrouter` 등이 있습니다 `[문헌]`. 기본으로 무엇이 선택돼 있는지는 모릅니다 `[미확인]`. 설정에서 `custom` 이 골라져 있는지 눈으로 봅니다.
   - **Presenton Cloud 를 연결하지도 고르지도 않습니다.** README 는 공급자로 Presenton 을 고르면 (`LLM=presenton`) 발표 생성과 **문서 올리기** 가 Presenton Cloud API 로 간다고 합니다 `[문헌]`. 처음 설정 화면에서 클라우드 연결을 권해도 건너뜁니다.
   - **웹 검색을 켜지 않습니다.** `WEB_GROUNDING` 이 `true` 면 웹 검색이 기본으로 켜지고, `WEB_SEARCH_PROVIDER` 의 `tavily` · `exa` 는 외부 검색 서비스입니다 `[문헌]`. `WEB_GROUNDING` 은 `false` 로 두고 검색 공급자 키를 넣지 않습니다. README 는 `auto` 가 OpenAI · Google · Anthropic 이 아닌 공급자에서는 검색을 끈 채로 둔다고 합니다 `[문헌]` — 데스크톱 앱의 기본값은 `[미확인]`.
3. **외부 그림 생성 · 검색을 끕니다.** `DISABLE_IMAGE_GENERATION` 이 슬라이드 그림 생성을 끈다고 합니다 `[문헌]`. 그림 공급자 `IMAGE_PROVIDER` 의 값에는 스톡 사진 `pexels` · `pixabay` 와 외부 생성 `gemini_flash` · `gpt-image-*` 등이 있고, 사내 `openai_compatible` 도 있습니다 `[문헌]`. 그림은 `deck.md` 에서 올리므로 생성 · 검색 공급자는 쓰지 않는 것이 맞습니다. 데스크톱 앱에서 끄는 칸은 `[미확인]`.
4. **사용 통계(telemetry).** `DISABLE_ANONYMOUS_TRACKING` 을 `true` 로 두면 끈다고 합니다 `[문헌]`. 기본이 켜짐인지는 README 에 없습니다 `[미확인]`. 데스크톱 앱에 이 값을 주는 방법은 `[미확인]` 입니다. 사용자 환경 변수로 두는 길이 후보이지만(값에 비밀이 없는 설정에 한함) 앱이 읽는지 확인하지 못했습니다 `[미확인]`.
5. **커뮤니티 갤러리.** README 는 커뮤니티 갤러리가 **기본으로 켜져 있고** Presenton 커뮤니티 서비스에서 디자인을 읽어 온다고 하며, 바깥과 끊긴 설치는 `PRESENTON_COMMUNITY_ENABLED=false` 로 꺼야 한다고 합니다 `[문헌]`. 끄면 화면에서 커뮤니티가 빠지고 갤러리 · 디자인 참조 요청을 보내지 않는다고 합니다 `[문헌]`. 데스크톱 앱에서 끄는 칸이나 이 값을 읽는지는 `[미확인]`.
6. **자동 업데이트.** README 에 없습니다 `[미확인]`. 끄는 법도 모릅니다.
7. 4 – 6 이 확인되기 전에는 **합성 자료로만 시험합니다.** 회사 방화벽에서 앱이 밖으로 나가는 연결을 막아 주는지 보안 담당과 상의하는 것도 방법입니다 `[제안]`.

## 3 deck.md 넣기

1. 먼저 합성 예시를 넣어 봅니다. 회사 자료는 2절이 끝난 뒤입니다.
2. README 로 확인한 것:
   - Presenton 은 글(프롬프트) · 올린 문서 · 내 PowerPoint 디자인에서 발표를 만듭니다 `[문헌]`.
   - API 쪽 설명에 `slides_markdown` (장마다 마크다운 한 덩어리 · 50개까지 · 한 덩어리 100단어까지가 기본, `MAX_OUTLINE_WORDS`) 이 있고, **"레이아웃은 LLM 이 고르며 글을 다시 쓸 수 있다"** · **"100단어를 넘는 덩어리는 잘린다"** 고 적혀 있습니다 `[문헌]`. 근거 줄 · 꼬리표가 붙은 장은 이 한도에 걸릴 수 있습니다 `[추정]` — 4절에서 장 끝 글머리가 남았는지 봅니다. 화면에서 붙여 넣는 길이 같은 규칙인지는 모릅니다 `[미확인]`.
3. 화면에서 모르는 것 `[미확인]`: 마크다운 파일 올리기 · 붙여 넣기 · `##` 대로 장을 나누는지 · 장 수를 정하는 칸 · '내용 그대로' 같은 선택이 있는지 · YAML 머리말(`---`)과 `:::` 줄을 글로 보이는지.
4. 해 볼 순서 `[제안]`: ① 붙여 넣기 칸이 있으면 `deck.md` 의 `## ` 장 하나를 붙여 넣어 결과를 본다 ② 맨 위 `---` 머리말과 `:::` 줄이 글로 나오면 그 줄만 지운 **붙여 넣기용 사본** 을 만든다 (원본 `deck.md` 는 고치지 않는다) ③ 장 수를 `deck.md` 의 `##` 수와 맞춘다. 되는 방법을 T22 에서 이 절에 채웁니다.
5. **그림 넣기.** 올리는 칸이 있는지 · `deck.md` 의 그림 경로 (자료 폴더 안의 파일 이름) 를 알아보는지는 `[미확인]`. 안 알아보면 그림을 화면에서 올리고 장에 놓습니다. 그림 속 글과 `imgN` 꼬리표가 그대로인지 봅니다.
6. 발표자 노트(`::: notes`)를 받는지는 `[미확인]`. 안 받으면 노트는 `deck.md` 에 남고 PPTX 에는 없습니다.

## 4 넣은 뒤 반드시 할 일

Presenton 은 LLM 으로 글을 다시 쓸 수 있습니다. 같은 합성 갈래에서는 숫자가 모두 맞았지만(M0 K6 · G2 100%) 그것이 매번 그렇다는 뜻은 아닙니다. `deck.md` 가 원본이고 Presenton 의 결과는 사본입니다.

1. **제목 목록을 대 봅니다.** 결과의 제목을 위에서부터 `deck.md` 의 `##` 제목과 한 줄씩 비교합니다 (머리 `현상 ›` 까지). 장이 늘거나 줄었거나 제목이 바뀌었으면 `deck.md` 대로 고칩니다.
2. **숫자와 꼬리표를 대 봅니다.** `[f003]` · `[추정 · img2]` · `[미확인]` · 답 id 와 숫자가 바뀌었거나 빠진 장은 `deck.md` 대로 되돌립니다. 사용자가 하지 않은 말(의견)이 새로 생겼으면 지웁니다.
3. **한계 장을 봅니다.** `한계 ›` 장과 `[미확인]` 글머리가 남아 있어야 합니다. 없어졌으면 `deck.md` 에서 가져옵니다.
4. 고친 것은 PPTX 에서 직접 고칩니다. 원본 `deck.md` 와 어긋나게 되면 `deck.md` 도 같이 고칩니다.

## 5 PPTX 로 내보내기

1. README 는 "편집할 수 있는 PPTX 로 내보낸다" 고 하고 API 의 `export_as` 는 `pptx`(기본) 또는 `pdf` 라고 합니다 `[문헌]`. 화면의 내보내기 단추 이름 · 위치는 `[미확인]`.
2. 내보낸 파일은 PowerPoint 로 열어 복구 대화상자 없이 열리는지, 글이 넘치지 않는지 봅니다.
3. **회사 양식.** README 에 '내 PowerPoint 디자인을 쓴다' · '기존 PowerPoint 파일에서 양식을 AI 로 만든다' 는 말이 있습니다 `[문헌]`. 회사 양식 파일을 올리면 그 파일이 LLM 으로 갈 수 있으므로 2절이 끝난 뒤에만 시험합니다. 되는지 · 얼마나 드는지는 `[미확인 — T22 에서 시간을 잰다]`.
4. **손으로 옮기는 후보** (회사 양식 파일에 슬라이드를 붙여 넣고 '대상 테마 사용' · '슬라이드 다시 사용'): `[미확인 — T22 에서 시간을 잰다]`.

## 6 저장된 것 지우기 (되돌리기)

1. README 가 말하는 저장 위치는 Docker 의 `app_data`(데이터베이스는 그 아래 SQLite, 설정 `userConfig.json`)뿐이고 데스크톱 앱의 위치는 없습니다 `[문헌]`. 데스크톱 앱이 올린 그림 · 만든 발표 · 설정을 어디에 두는지는 `[미확인]`.
2. 앱의 프로젝트(발표) 목록에서 만든 것을 지웁니다 `[미확인 — 지우는 화면]`.
3. 앱에 넣은 키는 설정에서 지웁니다. 사내에서 키를 다시 발급받아야 하는지는 사내 규정을 따릅니다.
4. 앱 제거는 Windows 의 앱 제거로 합니다 `[미확인 — 제거 프로그램이 남기는 폴더]`. 제거 뒤에도 사용자 데이터가 남을 수 있으니 1 의 위치를 확인한 뒤 직접 지웁니다.
5. 내보낸 PPTX 와 `deck.md` 는 자료 폴더에 있습니다. 원본 `deck.md` 는 지우지 않습니다.
