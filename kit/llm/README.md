# M0 시험지 — 사내 LLM · 그림 판독 (KIT-2 · KIT-3)

opencode 안의 사내 LLM 이 **그림을 실제로 받는지 · 도구를 부르는지 · deck 형식을 지키는지 (KIT-2)** 와 **차트 그림을 얼마나 바르게 읽는지 (KIT-3)** 를 회사 PC 에서 한 번에 잽니다. 기획의 근거는 [docs/PLAN.md](../../docs/PLAN.md) › 08 KIT-2 · KIT-3 과 09 리스크 2 · 3 · 5 · 19 · 22 입니다.

- **걸리는 시간**: 60분 안 (아래 [시간표](#시간표)).
- **쓰는 자료**: 이 폴더의 합성 그림과 합성 사실 목록뿐입니다. 이름 (PRD_A · EQ-01 …) 과 숫자는 모두 지어낸 것입니다. **회사 자료 · 회사 그림을 넣지 마십시오.**
- **두 자리**: 시험은 저장소 **밖**의 작업 폴더 (기본 `%USERPROFILE%\subordinate-m0`) 에서 하고, 채점은 저장소에서 합니다. 작업 폴더에는 모델이 볼 입력만 복사되고, 정답 · 채점기 · 이 README (문턱) 는 들어가지 않습니다.
- **남는 것**: 답과 deck 파일은 작업 폴더의 `results\` 에만 생깁니다. 개발 쪽에 넘기는 것은 채점기 출력 (숫자 · 판정 · 오류 이름) 과 걸린 시간뿐입니다.
- 이 키트는 M0 가 끝나면 지웁니다. KIT-1 · KIT-4 · KIT-5 (PC · 템플릿 · Office 확인) 는 `kit/env/` 의 별도 키트입니다.

> **[미확인]** 표시는 개발 쪽에서 확인하지 못한 것입니다. 해 보시고 결과를 답 칸에 적어 주시면 그것이 답이 됩니다.

## 주의 — 정답이 모델에게 보이지 않게

정답 (`kit/llm/synthetic/truth.json`) · 채점 규칙 (`kit/llm/score.py`) · 문턱 (이 README) 을 모델이 읽으면 시험이 무효가 됩니다. 그래서 **opencode 는 저장소가 아니라 작업 폴더에서 엽니다.** 작업 폴더에는 이 셋이 없습니다.

- 두 번째 방어선: 프롬프트는 모델에게 "적힌 파일 말고 다른 파일은 열지 말라" 고 합니다. opencode 화면에 모델의 도구 호출 줄 (파일 읽기 · 셸) 이 보입니다. 모델이 작업 폴더 밖 (특히 저장소) 이나 적히지 않은 파일을 연 것이 보이면 답 칸 `peeked` 에 `예` 를 적고, 그 항목만 새 세션에서 다시 하십시오.

## 준비 (5분)

1. 저장소를 받은 폴더 (맨 위) 에서 작업 폴더를 만듭니다 (cmd · PowerShell 둘 다 됩니다). 폴더가 이미 있고 비어 있지 않으면 덮어쓰지 않고 멈춥니다. 저장소 안의 폴더는 받지 않습니다.

   ```text
   python kit\llm\score.py prepare --out "%USERPROFILE%\subordinate-m0"
   ```

   PowerShell 에서는 `--out "$env:USERPROFILE\subordinate-m0"` 로 씁니다. `--out` 을 빼도 같은 자리입니다. 마지막 줄이 `결과: OK` 이면 됩니다. 들어가는 것: `inputs\` (그림 19장 · facts_lite · interview_lite) · `prompts\` (프롬프트 · 경로는 작업 폴더 기준) · 빈 `results\` · `ping.py` · 칸 이름만 든 `answers_template.json`.
2. **opencode 를 그 작업 폴더에서 엽니다.** 아래 표의 프롬프트 · 그림은 모두 이 작업 폴더의 것입니다.
   - 사내 LLM 연결 설정이 전역 설정 (`%USERPROFILE%\.config\opencode\opencode.json`) 에 있으면 그대로 됩니다.
   - 설정이 프로젝트 폴더 (예: `D:\OPENCODE\opencode.json`) 에만 있으면, 작업 폴더에서 연 opencode 는 그 파일을 읽지 못해 사내 모델이 목록에 없을 수 있습니다. 그때는 그 파일을 가리키고 엽니다 — cmd `set OPENCODE_CONFIG=D:\OPENCODE\opencode.json` · PowerShell `$env:OPENCODE_CONFIG = "D:\OPENCODE\opencode.json"` (그 창에서만 듭니다). 4단계의 백업 · `modalities` 수정도 이 파일에 합니다.
   - 어느 설정 파일이 쓰였는지는 결과 칸에 적지 않아도 됩니다. 사내 모델이 목록에 보이면 됩니다.
3. 답을 남길 곳을 정합니다. 둘 중 편한 쪽을 쓰시고, 섞어 써도 됩니다.
   - **answers.txt** (권장): 메모장으로 `작업폴더\results\answers.txt` 를 만들고, 모델이 답한 블록 (`c01.q1: …` 같은 줄) 을 받을 때마다 그대로 아래에 붙여 넣습니다. `칸: 값` 모양이 아닌 줄은 채점기가 건너뜁니다.
   - **answers.json**: `작업폴더\answers_template.json` 을 `작업폴더\results\answers.json` 으로 복사해 빈 칸을 채웁니다.
   - 사람이 직접 적는 칸 — `k2.attach` · `k2.b.config` · `k2.opencode` · `k2.question` · `k2.korean` · `peeked` — 은 어느 파일에 적어도 됩니다 (예: answers.txt 끝에 `k2.question: 선택화면`).
4. 지금 쓰는 `opencode.json` 을 복사해 둡니다 (예: `opencode.json.bak`). KIT-2 ㄱ 에서 한 줄을 더했다가 끝나면 되돌립니다.
5. 그림을 넣는 법은 두 가지를 준비해 두십시오 **[미확인 — opencode 에서 어느 쪽이 되는지 개발 쪽은 확인하지 못했습니다]**.
   - **붙여넣기**: 그림 파일을 opencode 입력 칸에 끌어 놓거나, 그림을 복사해 붙여 넣은 뒤 프롬프트를 붙여 넣습니다.
   - **읽기 도구**: 그림 없이 프롬프트만 보냅니다. 프롬프트에 그림 파일 경로가 적혀 있어서, 모델이 읽기 도구로 그 파일을 엽니다.
   - 처음 (KIT-2 ㄱ) 에 붙여넣기를 먼저 해 보고, 안 되면 읽기 도구로 하십시오. 된 쪽을 `k2.attach` 에 적습니다: `붙여넣기` · `읽기도구` · `둘다` · `안됨`.

- **그림 A 가 맞았으면 그림 B 는 건너뛰어도 됩니다** (그때 `k2.b.…` 칸은 비워 둡니다). 그림이 안 보인다고 하거나 엉뚱한 코드를 쓰면 B 를 합니다.
- ㅁ 은 붙여 넣기 전에 프롬프트의 `deck_1.json` 을 회차 번호 (`deck_2.json` …) 로 고칩니다. 다섯 번 모두 같은 프롬프트입니다. 모델이 파일을 못 쓰면 그 회차는 실패로 셉니다.
- opencode 판은 `opencode --version` 으로 보고 `k2.opencode` 에 적습니다 (숫자만).

### 그림 B 의 설정 — `modalities`

사용 중인 `opencode.json` 의 사내 모델 칸에 `modalities` 한 줄을 더합니다. 아래는 모양을 보이는 예시이고, 주소 · 이름은 자리표시입니다. 이미 있는 provider · 주소 · 키 칸은 그대로 두고 **`modalities` 줄만** 더하십시오. 키는 지금처럼 `{env:…}` 로 두고, 값을 파일에 적지 마십시오.

```json
{
  "provider": {
    "inhouse": {
      "npm": "@ai-sdk/openai-compatible",
      "options": {
        "baseURL": "https://llm.example.com/v1",
        "apiKey": "{env:INHOUSE_LLM_KEY}"
      },
      "models": {
        "inhouse-model": {
          "name": "inhouse-model",
          "modalities": { "input": ["text", "image"], "output": ["text"] }
        }
      }
    }
  }
}
```

- 이 키는 opencode 의 provider 설정 소스 (`provider.ts`) 에 있고 사용자 문서에는 없습니다 **[미확인 — 없을 때의 동작 · 판마다 같은지]**. 그래서 A (없음) 와 B (있음) 를 나눠 잽니다.
- 다시 시작했는데 opencode 가 설정 오류를 내면 `.bak` 으로 되돌리고 `k2.b.config: 오류` 라고 적어 주십시오.
- B 도 안 되면 같은 모델 칸에 `"attachment": true` 를 더해 B 를 한 번 더 해 볼 수 있습니다 **[미확인]**. 그때는 `k2.b.config: modalities+attachment` 로 적습니다.
- KIT-2 · KIT-3 이 끝나면 `.bak` 으로 되돌립니다. 그림이 B 에서만 닿았다면 되돌리지 말고 그대로 쓰셔도 됩니다 — 그 사실이 결과입니다.

## 채점 (5분)

채점은 **저장소 폴더에서** 합니다 (작업 폴더에는 채점기가 없습니다). opencode 가 아니라 cmd · PowerShell 에서 직접 치십시오.

```text
python kit\llm\score.py --dir "%USERPROFILE%\subordinate-m0\results"
```

`python` 이 없으면 `py` 로 합니다. `--dir` 을 빼면 `%USERPROFILE%\subordinate-m0\results` 를 먼저 보고, 없으면 저장소의 `kit\results\llm` 을 봅니다. 마지막 줄이 `결과: OK` · `결과: 확인 필요` · `결과: 점검 실패` 중 하나입니다 (종료 코드 0 · 3 · 1, 사용법 오류는 2).

- 채점기는 답 원문을 찍지 않습니다. 맞음 · 틀림과 알아본 값 (보기 이름 · 숫자 · 날짜), deck 오류의 이름만 찍습니다. **출력 전체를 그대로 대화에 붙여 넣으셔도 됩니다** — 모두 합성 자료에 대한 것입니다.
- `답 없음` 이 남은 칸이 있으면 판정이 `보류` 가 됩니다. 프롬프트 블록을 빠뜨리지 않았는지 보십시오.

## 판정 문턱 (결과를 보기 전에 적음)

이 표는 시험을 돌리기 전에 정한 것이고, 결과를 본 뒤에 고치지 않습니다. 같은 값이 `synthetic/truth.json` 의 `thresholds` 에 있고 채점기는 그 값을 씁니다.

**구간으로 판정합니다.** 5회 중 4회 통과의 95% 구간 (Wilson) 은 38–96% 라, 점 하나로는 좋고 나쁨을 가를 수 없습니다. 비율 항목은 모두 같은 규칙입니다.

- **초록**: 점 추정 ≥ 목표 **그리고** 구간 하한 ≥ 바닥
- **빨강**: 구간 상한 < 목표 (목표에 못 미친다는 것이 구간으로도 분명함)
- **노랑**: 나머지

| 항목 | 목표 · 바닥 | 초록 | 노랑 | 빨강 | 빨강 · 노랑이면 기획에서 바뀌는 것 |
|---|---|---|---|---|---|
| KIT-2 그림 도달 | — | A 또는 B 의 코드가 맞음 | — | A · B 둘 다 틀림 | 빨강: 그림 판독을 접고, 그림은 원자료로 다시 그리기 · 사용자 설명으로 받는다 (리스크 2). B 에서만 닿으면 INSTALL 에 `modalities` 단계를 필수로 넣는다 (T15) |

- **KIT-2 판정**: 초록 = 그림 도달 · 도구 호출 · deck 구조가 모두 초록. 빨강 = 셋 중 하나라도 빨강. 노랑 = 나머지.
- **KIT-3 판정**: 초록 = 범주 · 숫자 모두 초록. 빨강 = 둘 중 하나라도 빨강. 노랑 = 나머지.

- 마지막 줄: 둘 다 초록이면 `결과: OK`, 하나라도 빨강이면 `결과: 점검 실패`, 그 밖 (노랑 · 보류 · `peeked: 예`) 은 `결과: 확인 필요` 입니다.

## 결과 보내기

보내실 것은 [kit/README.md](../README.md) 의 "결과 보내기 — 6줄" 중 **K2 · K3 두 줄**입니다. 채점기가 마지막 `결과:` 줄 바로 앞에 `보낼 줄: K2 …` 와 `보낼 줄: K3 …` 를 찍으니, `보낼 줄: ` 을 빼고 옮겨 적으시면 됩니다.

- K2: `K2 <판정> <그림 A · B · X> <도구 호출 O · X> <question 도구 O · T · X> <deck 구조 통과 0-5>`. question 칸은 사람이 `answers.json` 의 `k2.question` 에 적은 값(선택화면 `O` · 글목록 `T` · 안함 `X`)이고, 안 적었으면 `?` 로 찍힙니다. 이때는 `?` 를 직접 `O` · `T` · `X` 로 바꿔 적습니다.
- K3: `K3 <판정> <범주 맞은 수 /17> <숫자 맞은 수 /9> <정답 파일을 연 일 0 · 1>`. 손으로 채울 칸은 없습니다(`peeked` 답을 적었으면 1).
- 판정이 `-` 이면 아직 안 한 시험입니다(보류).

## 되돌리기

- `opencode.json` 을 `.bak` 으로 되돌립니다 (그림이 B 에서만 닿았다면 그대로 두셔도 됩니다).
- 작업 폴더를 지웁니다. 합성 자료와 그 답만 들어 있고, M0 가 끝나면 남겨 둘 까닭이 없습니다. 다른 곳에는 아무것도 쓰지 않았습니다.

  ```text
  rmdir /s /q "%USERPROFILE%\subordinate-m0"
  ```

  PowerShell 에서는 `Remove-Item -Recurse -Force "$env:USERPROFILE\subordinate-m0"` 입니다.
- opencode 는 대화를 자기 데이터베이스에 남깁니다 (PLAN 리스크 9). 합성 자료뿐이지만, 지우고 싶으시면 opencode 의 세션 목록에서 이번 세션을 지우십시오.

### [미확인] 모음

- 사용자 정의 provider 모델에서 `modalities` 가 없을 때 opencode 가 그림을 넘기는지 (그림 A 가 답합니다).
- `"attachment": true` 가 그림 전달에 영향을 주는지.
- opencode 에서 그림을 넣는 법 — 붙여넣기 · 끌어 놓기가 되는지, 읽기 도구가 그림 파일을 모델에게 그림으로 넘기는지 (`k2.attach` 가 답합니다).
- opencode 가 2000 × 2000 을 넘는 그림을 줄이는 동작 [문헌: opencode 소스] 이 이 판에서도 같은지 (`c04L` 비교가 간접으로 답합니다).
- 사내 모델이 질문 도구 (`question`) 를 부를 수 있는지 (`k2.question` 이 답합니다).
