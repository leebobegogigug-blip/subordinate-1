# M0 기준선 비교 — 기성품으로 충분한가 (KIT-6)

**같은 합성 자료** 로 엔지니어링 보고 장표를 세 가지 방법으로 만들어 보고, 기획의 목표 (G1–G6) 를 매겨 봅니다. 기획 [docs/PLAN.md](../../docs/PLAN.md) › 08 의 **만들지 않을 기준** 을 판정하려는 것입니다 — 기성품 도구와 프롬프트만으로 G2 · G3 가 충분히 나오면 Subordinate–1 을 만들지 않고 프롬프트 묶음만 냅니다 (PLAN 09 리스크 16).

| 갈래 | 무엇 | 시간 목표 | 하는 일 |
|---|---|---|---|
| ① 손 작업 | 평소 쓰시는 방식 | 40분 안 (상한 · 넘겨도 실제 시간을 적음) | 시나리오 자료로 평소처럼 장표를 만듭니다 |
| ② Presenton | 오픈소스 AI 발표 생성기 (Windows 데스크톱 앱) + 사내 LLM | 30분 안 | 시나리오 글을 붙여 넣고 나온 것을 저장합니다 |
| ③ pandoc (선택) | 마크다운 › pptx 변환기 + `--reference-doc` | 20분 안 | 뼈대를 채워 변환합니다 |

채점은 갈래마다 15분 안쪽이고, 결과표는 [scorecard.md](scorecard.md) 의 표입니다. 처음부터 끝까지 한 번에 하실 필요는 없습니다. 갈래 사이에 쉬어도 되고 날을 나눠도 됩니다 (시계는 갈래 안에서만 잽니다).

> **[미확인]** 표시는 개발 쪽에서 확인하지 못한 것입니다 (Presenton 의 정확한 설정 화면 · 회사 템플릿 사용 여부 · pandoc 이 회사 템플릿을 받아들이는지). 해 보시고 본 대로 적어 주시면 그것이 답입니다.

## 먼저 읽어 주십시오 — 설치 승인

**Presenton · pandoc 은 이 PC 에 새로 설치해야 합니다. 회사 규정으로 승인이 필요할 수 있습니다.** 이 키트는 관리자 권한을 요구하지 않습니다 (RULES.md › W-08 과 같은 뜻). 아래 중 하나라도 해당하면 **그 갈래를 하지 마시고** 결과표의 그 갈래 칸에 `못 함` 이라고 적습니다.

- 설치에 관리자 권한 · 비밀번호가 필요하다고 나온다.
- 회사 정책상 승인이 필요한데 아직 받지 못했다.
- 실행하면 사내 보안 소프트웨어가 막는다.

`못 함` 은 실패가 아닙니다. 남은 갈래만으로 아래 판정 문턱을 적용합니다 (아래 [갈래가 모자랄 때](#갈래가-모자랄-때)). 승인을 받기 위해 이 저장소의 내용을 사내에 올리실 필요는 없습니다. 설치한 것은 끝난 뒤 지울 수 있게 어디에 설치했는지 적어 둡니다 ([되돌리기](#되돌리기)).

## 지킬 것

- **합성 자료만** 씁니다. 이 폴더의 [scenario.md](scenario.md) 와 `kit\llm\synthetic\` 의 합성 그림 · 합성 사실뿐입니다 (이름 PRD_B · EQ-03 · 숫자 모두 지어낸 것). **회사 자료 · 회사 그림 · 회사 장표를 어느 갈래에도 넣지 마십시오.** 회사 템플릿은 ① 의 평소 템플릿으로 쓰시거나 `--reference-doc` 경로로만 넘기고, 저장소 안으로 복사하지 않습니다.
- 작업 폴더를 따로 만들 필요는 없습니다. 자료는 저장소의 `kit\llm\synthetic\` 에서 읽기만 합니다. (`python kit\llm\score.py prepare` 로 만든 작업 폴더의 `inputs\` 를 쓰셔도 됩니다. 그림 이름 · 사실 목록이 같습니다. 필수는 아닙니다.)
- **Presenton 의 LLM 설정은 사내 LLM 을 가리키게 합니다.** 외부 LLM · 외부 그림 생성 · 외부 그림 검색 공급자는 켜지 않습니다. 합성 자료라도 기본값이 외부 공급자일 수 있으니 설정 화면에서 확인하십시오 **[미확인 — Presenton 의 기본 공급자 · 설정 화면 이름]**.
- **키는 Presenton 의 설정 칸에만 넣습니다.** 파일 · 시나리오 글 · 대화 · 화면 사진 · 명령줄 어디에도 적지 않습니다 (RULES.md › W-04). 결과표에도 키 · 사내 주소를 적지 않습니다.
- 결과 파일은 `kit\results\baseline\` 에 둡니다. 이 폴더는 git 이 무시합니다 (`.pptx` 도 무시합니다). **절대 커밋하지 않습니다.** 폴더가 없으면 만드십시오.
- 결과를 알려 주실 때는 **숫자와 예 · 아니오만** 적습니다. 파일 내용 · 제목 · 문장 · 경로는 적지 않습니다.
- Presenton 이 자료를 외부로 보내거나 자동 업데이트를 확인하는지 알 수 없습니다 **[미확인]**. 합성 자료만 쓰는 이유입니다. 설정에서 끌 수 있는 것은 끕니다.

2. 폴더를 만듭니다 (cmd · PowerShell 둘 다 됩니다).

   ```text

   ```

3. 그림을 한 번 열어 어떤 그림인지 확인합니다 (`kit\llm\synthetic\k2_ctx_1.png` – `k2_ctx_5.png`).
4. 시계를 준비합니다. 갈래마다 **시작 = 자료를 연 때 · 끝 = .pptx 를 저장한 때** 입니다. 순서는 ① › ② › ③ 을 권합니다. 앞 갈래에서 내용을 익히면 뒤 갈래가 빨라지는 영향이 있습니다 (순서를 바꿨다면 결과표 `메모` 에 적습니다).

## ② Presenton + 사내 LLM

1. Presenton 을 설치합니다 (Windows 데스크톱 앱). 설치 화면 · 설치 위치 · 관리자 권한을 요구하는지 확인합니다. 요구하면 중단하고 `못 함` 으로 적습니다. 어디에 설치했는지 적어 둡니다. **[미확인 — 설치 파일 이름 · 받는 곳은 개발 쪽이 확인하지 못했습니다. 프로젝트 공식 저장소 `presenton/presenton` 의 안내를 따르십시오.]**
2. 설정에서 LLM 공급자를 **OpenAI 호환 (사용자 정의)** 으로 두고, 주소 · 모델 이름을 사내 LLM 의 것으로 넣습니다. 키는 이 설정 칸에만 넣습니다. **[미확인 — 화면 이름 · 칸 이름 · 사내 LLM 이 이 앱의 호출 방식 (엔드포인트 모양) 을 받는지.]** 설정이 안 맞아 호출이 실패하면 오류의 종류만 적고 (키 · 주소는 적지 않습니다) `못 함` 으로 처리합니다.
3. 외부 그림 생성 · 검색 공급자를 끕니다 (또는 사용 안 함). 못 끄면 그 사실을 `메모` 에 적습니다.
4. 시계를 켭니다.
5. [scenario.md](scenario.md) 의 "② Presenton 에 붙여 넣을 글" 상자를 통째로 붙여 넣고 생성합니다. 그림 올리기가 있으면 img1–img5 를 올립니다.
6. 나온 장표를 봅니다. 고칠 것이 있으면 Presenton 안에서 고치거나 다시 시켜도 됩니다. **다시 시킨 말은 하나씩 세어 두십시오 (G6).** 본문 글자를 직접 손봤다면 시간에 넣되 G6 에는 넣지 않습니다.
7. .pptx 로 내려받아 `kit\results\baseline\presenton.pptx` 로 저장하고 시계를 끕니다. 내보내기가 .pptx 를 못 주면 `못 함` 입니다 **[미확인 — 내보내기 형식]**.
8. (문턱을 넘을 것 같으면 · 아래 [재실행](#재실행)) 새 프로젝트로 한 번 더, 같은 글로 합니다. 결과는 `presenton_2.pptx` 로 저장합니다.

## ③ pandoc (선택)

1. pandoc 설치를 확인합니다. 이미 있으면 `pandoc --version`, 없으면 설치합니다 (관리자 권한 없는 판 — 압축 풀어 쓰는 판 — 이 있는지 pandoc 공식 안내를 봅니다 **[미확인]**). 승인이 필요하면 중단하고 `못 함`.
2. `kit\results\baseline\pandoc\` 폴더를 만들고, [scenario.md](scenario.md) 의 마크다운 뼈대를 `deck.md` 로 저장합니다.
3. 시계를 켭니다.
4. 뼈대의 괄호 `( … )` 를 채웁니다. 제목은 직접 쓰거나 사내 LLM 에게 시켜 받아 쓰고, 누가 썼는지 적습니다. 사실 · 의견은 scenario.md 에 있는 것만 씁니다.
5. 변환합니다 (`deck.md` 가 있는 폴더에서).

   ```text
   pandoc deck.md -o ..\pandoc.pptx
   ```

   회사 템플릿으로 해 보고 싶으면 (선택 · 이것도 시계 20분 안에서):

   ```text
   pandoc deck.md --reference-doc "템플릿경로.pptx" -o ..\pandoc.pptx
   ```

   템플릿 경로는 이 문서에도 결과에도 적지 않습니다. pandoc 이 오류를 내거나 장표가 이상해지면 오류 종류만 적고 첫 줄 (기본 모양) 으로 합니다 **[미확인 — 회사 템플릿의 레이아웃 이름 · 마스터와 pandoc 이 맞는지]**.
6. `kit\results\baseline\pandoc.pptx` 가 만들어졌으면 시계를 끕니다.

## 채점 (갈래마다 15분 안쪽)

[scorecard.md](scorecard.md) 를 따라 합니다. 순서: G3 (제목만 읽기) › G2 (`trace_numbers.py`) › 엔지니어 입에 넣은 의견 › G5 (회사 PowerPoint 로 열기) › G4 (더 드는 시간 추정) · G6.

```text
python kit\baseline\trace_numbers.py kit\results\baseline\hand.pptx --interview kit\llm\synthetic\interview_lite.json
python kit\baseline\trace_numbers.py kit\results\baseline\presenton.pptx --interview kit\llm\synthetic\interview_lite.json
python kit\baseline\trace_numbers.py kit\results\baseline\pandoc.pptx --interview kit\llm\synthetic\interview_lite.json
```

`python` 이 없으면 `py` 로 합니다. 이 도구는 파일을 읽기만 합니다. 마지막 줄이 `결과: OK` · `결과: 확인 필요` · `결과: 점검 실패` 중 하나입니다 (종료 코드 0 · 3 · 1, 사용법 오류는 2). 장표 글은 찍지 않고 안 맞는 숫자만 찍습니다. 출력 전체를 대화에 붙여 넣으셔도 됩니다 (합성 자료의 숫자입니다).

## 판정 문턱 (결과를 보기 전에 적음)

이 절은 갈래를 돌리기 전에 정한 것이고, 결과를 본 뒤에 고치지 않습니다. 근거는 PLAN 08 의 "만들지 않을 기준" 입니다. 개발 쪽이 PLAN 의 초안에서 바꾼 것은 아래 "초안에서 바꾼 것" 에 모두 적었습니다.

### 규칙

**② 와 ③ 중 가장 잘한 한 갈래** (G2 비율이 높은 쪽 · 같으면 G3 가 높은 쪽 · 같은 갈래가 아래를 모두 채워야 합니다) 가 다음을 **모두** 채우면 **만들지 않는다.**

1. G2: 비율 80% 이상 **그리고** 지어낸 숫자 (안 맞음) 0 — `trace_numbers.py` 가 `결과: OK`.
2. G3: 4점 이상.
3. G5: 예 (복구 대화상자 없이 열림).
4. 엔지니어 입에 넣은 의견 0개.
5. G4: 0 · 10 · 30 중 하나 (추정 30분 이하. 60+ 이면 못 채운 것). 이 한 줄은 PLAN 초안에 없던 것입니다 — 아래 "초안에서 바꾼 것".

하나라도 못 채우면 **만든다.** 만드는 경우는 어디서 부족했는지로 둘로 나눕니다.

| 판정 | 조건 | 계획에서 바뀌는 것 |
|---|---|---|
| **만들지 않는다** | 위 다섯을 모두 채움 (그리고 ② 가 채웠다면 [재실행](#재실행) 도 채움) | T4 (5판) 에서 PLAN 08 의 M1–M4 를 접는다. 앱 · 어댑터 · 파이썬 패키지를 만들지 않는다. 대신 질문 은행 (PLAN 05 · 부록 B) · 보고 문법 (04) · 템플릿 매핑 방법을 **프롬프트 묶음** 으로만 낸다 (그 갈래의 도구 + 사내 LLM 용). 리스크 16 을 닫고 G1–G6 은 그 묶음의 시험 기준으로 남긴다. 이때도 KIT-2 · 3 의 사내 LLM 결과는 그 프롬프트 묶음 설계에 쓴다 |
| **만든다 (중간)** | G2 는 통과 (80% 이상 · 지어낸 숫자 0) 인데 G3 · G5 · 의견 · G4 중 하나 이상 못 채움 | 계획대로 만들되, **어디서 졌는지가 곧 제품의 가치** 로 적힌다. G3 가 졌으면 보고 문법 · 제목 검사 (P-02 · P-06) 를, 의견이 졌으면 V-02 (LLM 의견 차단) 를, G5 가 졌으면 직접 조립 (`python-pptx`) 의 근거를, G4 가 졌으면 템플릿 매핑 · 인터뷰의 근거를 5판의 목표 칸에 단다. 그 갈래의 좋았던 레이아웃 · 프롬프트 문장은 재사용한다. 예: ② 가 G2 는 통과하고 G3 에서 졌으면 만든다 — 대신 ② 의 장 구성 · 프롬프트 문장을 인터뷰 · 장표 설계에 가져온다 |
| **만든다 (미달)** | 두 갈래 모두 G2 미달 (80% 미만 또는 지어낸 숫자 1개 이상) | 계획대로 M1 부터. PLAN 의 핵심 주장 (결정적 도구가 숫자를 근거에 묶는다 · V-03) 이 서 있다는 증거가 되므로 5판에서 이 숫자를 그대로 인용한다. 기성품은 기준선으로만 남긴다 |
| **보류** | ② 와 ③ 이 모두 `못 함` | ① 의 시간 (G1) · G3 · G4 만 5판에 적고 **계획대로 만든다 (기본값)**. 기성품은 시험하지 못했다고 [미확인] 으로 남기고, 회사에서 설치가 허용될 때 다시 돌린다 |

### 갈래가 모자랄 때

- ② · ③ 중 하나만 돌렸으면 그 갈래 하나에 규칙을 적용합니다. 이때 결론이 **만들지 않는다** 이면 "다른 한 갈래 미시험 [미확인]" 을 5판에 같이 적습니다.
- ① 은 규칙의 조건이 아니라 기준선 (G1 의 1/3 을 재는 분모 · G3 · G4 의 비교) 입니다. ① 을 못 했으면 PLAN G1 의 '손 작업의 1/3' 은 [미확인] 으로 남깁니다.

### 재실행

LLM 은 같은 글에도 다르게 답합니다. 한 번의 운 좋은 결과로 프로젝트를 접지 않으려고, **② 가 한 번에 위 다섯을 채웠을 때만** 같은 글 · 새 프로젝트로 한 번 더 돌려 (30분 안) 같은 채점을 합니다. 두 번 모두 채워야 **만들지 않는다** 입니다. 첫 번째에 이미 못 채웠으면 더 돌리지 않고 **만든다** 쪽으로 갑니다. ③ 은 사람이 문장을 쓰므로 재실행하지 않습니다.

### 초안에서 바꾼 것

PLAN 08 의 초안 한 줄은 "② 가 G2 · G3 를 프롬프트만으로 80% 채우면 만들지 않는다" 입니다. 다음을 더했습니다.

- G2 의 80% 에 **지어낸 숫자 0** 을 더했습니다 (PLAN 09 리스크 3 · 장표에 지어낸 숫자 한 개가 나오면 도구가 끝납니다).
- G3 의 80% 는 5점 척도로 읽어 **4점 이상** 으로 했습니다 (PLAN 01 의 G3 문턱과 같습니다).
- **G5 와 엔지니어 입에 넣은 의견 0** 을 더했습니다 (PLAN G5 · P-01. 열리지 않는 파일 · 사람 말을 지어내는 도구는 프롬프트 묶음으로 낼 수도 없습니다).
- **G4 30분 이하** 를 더했습니다. 프롬프트 묶음만 내는 결정은 사용자가 결과를 거의 그대로 낼 수 있다는 뜻인데, 고칠 것이 많으면 그 전제가 서지 않습니다. 그래서 G4 가 60+ 이면 **만든다 (중간)** 으로 봅니다. 이 문턱은 [제안] 이고 결과를 본 뒤 바꾸지 않습니다.
- 같은 갈래가 모든 조건을 채워야 한다 · ② 재실행 · ② 와 ③ 중 높은 것을 쓴다는 규칙을 더했습니다.
- G1 · G6 은 규칙에 넣지 않습니다. 기성품이 느려도 (G1) 프롬프트 묶음은 사용자의 평소 방식 위에서 쓰이므로 문턱이 다르고, G6 은 도구마다 질문 방식이 달라 비교가 어렵습니다. 둘은 기록해 5판 목표에 반영합니다.
